## 字面量与常量的目录格式

格式 5 引入以下表示；当前格式 6 完整保留这些规则：

- `programTextFormat: ide-literals-v1`。普通程序页按 IDE 原文显示文本；每页以 `literalFormat: ide|legacy` 明确语法。字符串内部的 CRLF、LF、CR、制表符、ASCII 引号和真实标记前缀均作为内容；路径反斜杠及字面量 `\n`、`\t` 不作为转义。
- `SourceTextCodec` 在目录边界与内部规范表示之间双向转换，不解释声明备注和注释。仅规范化字符串外的行结束；按本地编码字符边界扫描，避免跨两个汉字误识别中文引号。
- 原生页转换记录内部行到用户实际物理行的对应关系，用于预检诊断。整行编码、表达式长文本、NUL 等已识别为不能无损显示的程序页保留显式 legacy 语法。中文结束引号等歧义输入尚未全面解决。
- `constantTextFormat: ide-long-text-v1`。`LongTextConstantCodec` 使常量表显示 IDE 的 `<文本长度: N>`，完整值保存在 `text/*.txt`，索引在 `text/list.json`。内部语义解析仍拿到完整的编码值。
- 长文本索引按常量名绑定，文件名通常来自原生 ID，但该 ID 可能因语义重建改变；读者必须查询索引，不能依赖固定文件名。改名需同步更改索引 `name` 和源码引用。修改完整文本后，可用 `update` 刷新显示长度；`pack` 不改写输入目录。
- 缺失值文件/索引、重复名称绑定、修改显示长度或未知格式会明确失败。移除了孤立长度占位符生成 N 个空格的行为，防止静默丢失内容。
- 旧目录缺少新格式标记时按旧语法读取；不能交给不理解格式 5 的旧工具封包新目录。不要仅改元数据宣称完成语法转换。

## 格式 6：同名调用身份与显示分离（2026-11-14）

`format5-name-identity-loss/result.json` 证明简单删除 `krnln::` 后修改路径，会将两处核心库调用变成同名成员方法。格式 6 因此新增 `SourceCallBindingCodec`，而不是取消名称绑定检查。

- `SourceExpressionNode` 记录名称的源码字节范围。仅对 AST 中调用位置的限定名称改写，不替换字符串、注释、类型声明或对象成员名。
- 目录 `programCallFormat: provenance-v1` 和每页 `callBindings` 标记指向 `project/.call_bindings.json`。文件只保存确实需要隐藏限定符的页面原始规范源码，不保存可替代语义编译的整段方法字节码。
- 写出时仅页面显示去掉限定；读入时先恢复内部字面量，再按同一方法的完整语句 AST / 忽略字面量值的结构匹配恢复调用目标。所有调用都参与原始语句签名，防止把同名成员调用误当成核心库调用。
- 未变化的语句序列按位置恢复；不同语句可按唯一语法树重排。方法改名仅在方法体结构唯一时支持。显式 `库::命令` 是用户覆盖目标的输入。
- 歧义、超出来源数量的新裸调用、无法解析的新语句均报错，要求明确限定；缺失文件、缺失页记录、缺失新格式标记也报错。不会通过回滚旧方法体掩盖失败。
- `update` 会基于已恢复的规范源码重写绑定来源。旧目录仍按原来的限定语法读取。
- 此匹配是保守的编辑支持，并非任意重构的身份追踪。跨页移动、复杂包装/参数结构更改可能需要显式限定。两个完全相同的可见表达式若拥有不同目标，交换后文本本身没有可观察变化；必须用显式限定表达意图。
- `<对象>` 完全未改动。

最终实际 IDE 基准重放：两个架构均 **49/50 页严格比较一致**；唯一差异是同名根类声明中的 `<对象>`。逐页 diff 没有忽略这个差异。若按用户授权排除此项，50/50 页均符合本轮对照要求。仍遵循前文的头信息/字符串外空白比较规则，并非系统剪贴板原始字节比较。

### 遗留名称问题的进一步定位

`format6-existing-placeholder-analysis.json` 显示两个停用语句中的变量引用 ID 分别为 `0x2502B8DB`、`0x2501E217`；对应方法仅保留另一个局部变量 ID，项目所有方法的参数/局部定义均无被引用 ID。这些占位不是源码字符串中的原文，也不是本次绑定转换产生的；是原生停用表达式仍保留引用而定义已缺失。不能直接替换为最近的局部变量名。

样本 0109 的公开方法 `置外形路径` 参数保存类型 `0x490160FE`，主工程快照无对应类定义。引用模块中的同名方法参数为另一个 ID `0x490119B0`，对应匿名类，尚缺可靠的跨模块映射证据。未按方法名或参数位置猜测其真实类型。

因此，本轮结论是目标显示差异修正且未引入已测回包退化，不能宣称全部历史未知符号均已解决、所有任意编辑都可自动绑定，或全部源文件均能与 IDE 原文逐字一致。上述三处问题仍在失败清单中。未提交、安装或部署。
