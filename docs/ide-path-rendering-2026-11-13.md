# 普通路径与命令作用域的导出修正

## 历史目的与复现

同一个 `12.e` 在官方 v1.2.16 中导出为：

```text
a ＝ 读入文件 (取运行目录 () ＋ “\xx\”)
```

已安装的 v1.2.27 导出为：

```text
a ＝ 读入文件 (krnln::取运行目录 () ＋ “#e2txt_text#\\xx\\”)
```

提交 `9a439772ec0e320c0341b24aa2f1378a71a514d2`（2026-10-08；首次包含于 v1.2.18 标签）把表达式字符串改为使用已有的转义载荷格式，并在同名支持库调用上增加限定。两项改动都有语义回包目的：

- 转义载荷保存真实换行、控制字符、引号以及恰好以内部标记开头的字面文本。旧版原样导出普通字符串，并不能证明复杂字符串同样可无损重建。
- 名称限定保留支持库命令的身份。`TestSupportCommandResolution.ps1` 同时调用同名 DLL 和核心库的“打开文件”，只删除前缀会让支持库调用被用户声明遮蔽。

`12.e` 的冲突来自精易模块另一个对象类“类_环境存取”的成员“取运行目录”。该成员对当前窗口程序集的非限定调用不可见；将所有类成员扁平放入全局名称集合是过度判定。

## 本次调整

1. 易语言中文引号中的反斜杠是普通字符，不再单独触发载荷转义。`\xx\`、`C:\new\test.txt`、字面 `\n\t` 保留原文。若字符串还含控制字符等必须编码的内容，仍编码完整载荷并正确还原反斜杠。
2. 支持库名称冲突按照全局声明、当前类及继承链判断，其他对象类的成员不再污染全局。模块内联后的 owner ID 先映射到承载方法的代码页；无基类/根对象哨兵不参与地址别名映射。
3. 保留旧工作区的转义解码、真正重名调用的限定和复杂文本保护。没有直接撤销原提交，也没有全局剥离字符串前缀。

这是对本例两项过度保护的修正，不代表所有导出文本已经逐字等于 IDE 剪贴板格式。真正的名称歧义、控制字符及长文本仍使用现有无损格式。若要求这些场景也输出完全原生文本，需要分别核对 IDE 的格式和名称绑定规则，并设计可编辑后仍可靠的身份保存方式，不能仅删除标记。
