# 原生符号身份与 IDE 显示一致性（2026-11-14）

本轮继续处理 `_Local_`、`_Cls_` 显示及编辑后的语义回包。用户确认 `<对象>` 不处理，相关逻辑保持原样。改动位于 e-packager；没有提交代码或部署 AutoLinker 插件。

## 为什么不能直接删除占位名称或回滚

此前 `12.e` 的路径转义和 `krnln::` 差异来自内部表示泄漏到可见源码。历史修改原本用于保留特殊文本和调用身份；简单去掉限定符会让核心支持库调用误绑到同名成员。该问题已由格式 5/6 的字面量转换和调用绑定处理，本轮保留这些规则。历史调查见 `ide-source-parity-2026-11-13.md`。

本轮三个样本的事实不同于“普通变量被错误改名”：

| 样本 | 原生事实 | 实际 IDE 表现 |
|---|---|---|
| 0638，精易模块 v8.4.5 | `缩略图_创建` 中六处停用条件引用 `0x2502B8DB`，对应声明已不存在 | 操作数为空；首个停用判断实际复制为 `.判断开始断` |
| 0674，黑月界面类 | `创建W` 中一处停用条件引用 `0x2501E217`，对应声明已不存在 | `.' 如果真 ( ≠ 0)` |
| 0109，Ex_DirectUI | 导入接口参数保存类型 `0x490160FE`，本工程没有对应类型定义 | `.参数 路径, , 参考` |

不能按变量名形状、最近的局部变量、模块中的同名方法或参数位置猜测这些 ID 的含义。真实声明即使恰好叫 `_Local_0x1E217`，也必须仍作为普通用户变量处理。

旧语义回包在无法解析停用条件时，将整行写入流程调用的未检查文本槽，却仍设置停用标志 `0x20`，没有编码操作数。实际 IDE 会显示重复条件。将标志直接改成 `0x60` 的独立试验仍然重复，不能据此修复。

## 实现方式

- 同一个原生语法树生成内部规范视图和 IDE 显示视图。真正缺失的用户符号在显示视图中留空；内部保留其原生身份及无冲突别名。
- 新增 `SourceIdentityCodec`。目录格式为 7，`programIdentityFormat: native-views-v1`，每页 `identityBindings` 与 `project/.source_identity.json` 对应。侧车保存两份源码的对应关系，不用它代替方法体语义编译。
- 回包在同一方法中按唯一语句对应关系恢复身份；支持原样文本和字面量、注释编辑。显式填写新的变量或类型覆盖原有空白引用。
- 方法改名、跨方法移动或空类型声明改名后，若无法证明隐藏身份的对应关系，返回 `unmatched_native_identity`。多个可见语句对应不同原生身份时拒绝猜测。
- 内部别名在拆包时避开真实声明；编辑后新增声明若与已有内部别名对应不同 ID，返回 `native_identity_name_conflict`，不能误绑到新变量。
- 变量身份补入最终语义编码上下文。源码改变后，既有 `sourceTextMatchesNativeSnapshot` 策略禁止复用方法体/语句字节；只保留声明、依赖和原生引用身份。
- 无法语义解析的停用流程明确失败，不再伪造带整行文本的流程调用。普通注释、字符串及真实占位样式名称不参与身份猜测。
- `update` 保持当前显示视图；旧格式 6 的规范源码仍可读取。缺少身份文件、页记录、格式标记或结构损坏均明确报错。不要将格式 7 目录交给不认识该格式的旧工具。

## 回归中额外发现的两个格式边界

**空注释不是无注释。** 原始文件存在长度非零、内容全 NUL 的注释槽。纯空注释行以及可见空行尾注释均须保留。回包采用可选值区分“没有注释”和“显式空注释”，并单独保留循环首尾注释与停用标志。

IDE 对注释槽的长度也有要求：只有终止符的 BSTR 不显示注释；显式空注释以一个 NUL 内容字节加终止符编码。这个规则由原文件抽出的返回语句和最小两 NUL 探针在真实 IDE 中验证，两者实际复制内容一致。不是根据某个样本文件名或占位文字加例外。

**手写零行流程体需要原生空白行。** 缺少任何语句的分支/循环体虽可被解析，却可能令 IDE 在显示时异常。现在与已有空子程序处理一致，在空嵌套块内生成一个原生空白语句，供编辑器定位光标和流程线。保留空分支的专项产物已在真实 IDE 打开并复制验证。

## 原始证据与独立核对

证据根：`E:/temp/symbol-parity-20261114/`。

原 `.ec` 缺少编辑器行/块索引，不能将旧回包结果当作原始源码基准。因此用可载入的命名外壳承载原文件的目标方法表达式和引用表，只独立重算编辑器索引。原始载荷在原文件中唯一出现，并记录了原始字节证明。

- 两个 `_Local_` 方法：原始载荷在 IDE 的 Ctrl+A/C 结果、最终拆包文本、最终语义回包后 Ctrl+A/C 结果一致。只排除方法末尾的额外分隔换行。
- 两个架构分别核对原始和最终停用表达式：条件 AST、操作数及缺失 ID 引用次数相同；最终标志为 `0x20`，未检查文本槽为空。
- `_Cls_` 参数：从原文件复制完整原生参数块构造独立 IDE 探针，确认其类型栏为空。最终拆包与再拆包均为空白，参数原生类型仍为 `0x490160FE`。没有通过同名模块接口猜测类型。
- 空注释和空流程体：最终原生文件在实际 IDE 的复制结果与拆包文本一致；同时保留了此前无效编码和零行流程体的失败记录。

主要证据：`case-638/clipboard-original.txt`、`case-674/clipboard-original.txt`、两例的 `clipboard-release.txt` 与 `release-parity.json`、`case-109/clipboard-original-type.txt`、`empty-inline-oracle/`、`empty-inline-two-nul/`、`release-comment-ide/`、`release-original-identities.json`。

## 最终全量回归

最终产物冻结在 `bin-release/`，测试期间不修改二进制。复用先前相同的 20 个 `.e`、20 个 `.ec` 样本及完整依赖副本树；Win32/x64 共 80 条流水线。没有替换失败样本，没有修改原文件，也没有豁免未解析名称。

`release-regression/` 结果：

- **80/80 通过**拆包、无修改回包、每页追加注释后的语义回包、再拆包、第二次回包。
- **80/80** 无修改回包与输入字节一致。
- 源码逐字比较，仅统一 CR/LF 换行形式，保留空行、缩进和行尾内容；源码、资源、注释标记和未解析名称检查均通过。
- 40 个实际原文件再次按 SHA-256 核对，全部未改变。
- 相比格式 6 已验证的语义回包结果，两个架构合计 **42,660 个方法**中，42,656 个原生语义结构相同；仅上述两个问题方法各出现一次预期修正。声明、参数类型、局部变量类型均无差异。

专项脚本覆盖 `12.e` 连续路径编辑、同名调用绑定、复杂字面量、旧版未检查文本、长文本完整值、身份名称碰撞、显式替换操作数、无效停用条件拒绝，以及空注释/空流程体。身份侧车缺失和损坏、`update`、格式 6 兼容另有独立集成验证。结果见 `release-specials/`、`release-identity-edges/`、`cpp-tests/`。
