# 方法可达性与标量代码生成

`compile` 的 semantic 后端提供三个可比较的档位，默认为 `typed`：

```powershell
e-packager compile project out.exe --arch x86 --semantic-opt typed --optimization-report out.optimization.json
```

| 档位 | 行为 |
| --- | --- |
| `baseline` | 保持原有生成方式，作为差分测试基线 |
| `reachable` | 在生成前绑定调用并求可达闭包，只生成闭包内的方法 |
| `typed` | 在可达性分析基础上，对满足条件的整个方法生成标量 C++ |

选项同时支持 `--semantic-opt=typed` 和 `--optimization-report=out.json`。传统后端会明确拒绝这些选项。报告写入失败会使编译命令失败；报告路径不能覆盖输入工程或输出程序。

## 分析与 ABI 边界

入口包括启动子程序、模块初始化、受支持的窗口/控件事件和 DLL 导出。分析继续追踪直接调用、取子程序地址、实例化类型的生命周期、继承和虚方法分派。调用绑定与生成共享同一个解析器；生成期间发现分析闭包之外的方法会报错，不会静默补入。

当前使用程序级保守边界：可达机器码、外部调用、回调地址、DLL 导出或原生复合类型可能访问无法界定的对象时，保留原生类方法表闭包及初始化入口。此时不压缩、重排或填空原生方法槽。纯语义对象无需原生方法表。实现不按工程名、模块名或支持库名称设置例外。

这是保守分析，尚未实现逐对象逃逸分析；原生调用很多的工程可能几乎不减少方法数。程序集变量和全局变量也仍按现有生命周期保留，未实施变量级裁剪。

## 标量生成范围

首版覆盖普通非类方法的基本数值/逻辑参数、局部变量、赋值、返回、比较、算术、条件分支、循环和已确认可生成的直接调用。递归的纯标量调用组可整体生成。内部直接调用使用标量参数；通用调用方、事件及导出继续经过原有 `Value` 边界包装。

方法整体降级的情况包括：类方法、数组/文本/字节集/复合值、可空或传址参数、地址表达式、静态局部变量、非局部访问、外部调用、机器码、返回动态类型与声明不一致，以及有隐式空返回的标量方法。降级会向调用方传播，每个方法都有可查看的原因。整除/取余暂不生成标量代码，因为有符号最小值除以 `-1` 的行为尚未统一。

标量生成保持**现有通用运行时**的数值语义：整数存储使用 `long long`，浮点存储使用 `double`；加减乘除及比较按现有浮点转换执行，除零返回零，逻辑操作不引入短路，`>`/`>=` 保留既有否定比较规则。这不是对原生 IDE 的所有溢出、窄化或非有限浮点行为的等价承诺，也不在优化过程中顺带修正这些语义。可用 `baseline` 保留原生成路径并进行差分验证。

## 报告与验证

`native_boundaries` 逐项记录原生边界的触发原因、目标、所属方法和源码行，`native_boundary_counts` 按类别汇总。类型生命周期以类型编码和名称标识，未执行分析的 baseline 不把空列表解释为已证明安全。

JSON 报告记录方法总数、可达/强类型/通用方法数、原生包装数、每个方法的保留原因和调用边、强类型降级原因、C++ 源码字节数、编译耗时、EXE 大小及 PE 各节大小。所有体积都取自刚链接完成的产物，不经过 UPX；不要将其与已加壳的 IDE 产物直接比较。

测试入口：

```powershell
./tools/TestSemanticOptimization.ps1
./tools/TestDirectCompilerSemantics.ps1 -SemanticOpt typed

# 使用与目标架构匹配的宿主和核心库：
./tools/TestSemanticOptimization.ps1 -Packager ./bin/x64/Release/e-packager.exe -Architecture x64 -CoreDirectory <x64核心库目录>
```

`TestSemanticOptimization.ps1` 对同一个临时工程编译、运行三档产物，验证死类裁剪、标量调用与递归、数值转换、原生包装移除和有明确原因的降级。测试不会修改原始 `.e` 文件。x86 测试还实际调用 DLL 回调及传址参数，检查原生方法表完整保留。独立的 `TestNativeX86Abi.ps1` 需要其夹具目录存在有效文件；缺失时明确失败，不能把空模板运行成功算作 ABI 回归。

## 2026-09-17 验证结果

Release Win32/x64 构建通过；两种架构的三档差分运行通过。x86 覆盖实际 DLL 回调和传址；Win32/x64 均实际编译并调用三档 DLL 导出；语义回归覆盖机器码、模块初始化、继承和 DLL 文本/二进制/结构体。控制台和窗口模板在两种宿主下的 4 次拆包回包字节校验通过。没有执行全量模块测试。

| 工程/架构 | baseline 字节 | reachable 字节 | typed 字节 |
| --- | ---: | ---: | ---: |
| 标量、循环、继承夹具 / x86 | 248,320 | 241,664 | 226,816 |
| 同一夹具 / x64 | 222,720 | 222,720 | 206,336 |
| 高级取色器 V2 修复副本 / x86 | 18,781,696 | 18,781,696 | 18,780,160 |

取色器共 6,121 个方法，三档均保留 5,219 个，`typed` 生成 17 个标量方法；4,878 个原生类包装仍需保留。其 `.text` 从 17,264,640 降至 17,263,616 字节。这证明当前保守实现尚未解决该工程的主要体积来源，不能将小夹具的收益外推到大型原生模块工程。

取色器按钮烟测保持响应并正常退出，拖拽捕获/释放通过。解锁桌面后，实际屏幕取色与颜色标签像素校验通过：期望颜色、编辑框值及标签背景像素均为 3646696，坐标与目标窗口信息正确。完成验收后默认档位切换为 `typed`；可显式选择 `baseline` 回到原生成路径。

## 原生包装共享与尺寸优先编译

优化档位的 x86 原生类入口使用共享参数桥接函数，按静态描述表读取参数并完成传址写回。原生方法槽、入口调用约定、可空参数的存在标志、64 位参数的字宽和各类返回值约定保持不变。`baseline` 保留旧包装供差分使用。共享桥接不依据任何工程、支持库或模块名称选择行为。

`--codegen-opt size` 使用 MSVC `/O1`，`--codegen-opt speed` 使用 `/O2`。默认仍为 `speed`，这是独立于 `--semantic-opt` 的选项。两种写法 `--codegen-opt size` 和 `--codegen-opt=size` 均可用，传统后端拒绝显式使用该选项。JSON 报告的 `codegen_optimization` 字段记录策略。

```powershell
e-packager compile MyApp.e MyApp-small.exe --arch x86 --codegen-opt size --optimization-report MyApp-small.json
./tools/TestSemanticOptimization.ps1 -CodegenOpt size
./tools/TestDirectCompilerSemantics.ps1 -SemanticOpt typed -CodegenOpt size
```

尺寸优先可能牺牲热点性能，不自动替换速度优先默认值；应按实际负载测量选择。报告中的体积均为未压缩产物。

取色器 V2 修复副本的实测结果（同一源工程、x86、未压缩）：

| 包装实现 | C++ 优化 | EXE 字节 | .text 字节 |
| --- | --- | ---: | ---: |
| 原逐方法包装 | /O2 | 18,780,160 | 17,263,616 |
| 原逐方法包装 | /O1 | 14,003,200 | 12,577,280 |
| 共享参数桥接 | /O2 | 15,762,432 | 14,047,232 |
| 共享参数桥接 | /O1 | 12,018,688 | 10,388,480 |

两种新产物均保留 5,219 个方法和 4,878 个原生包装入口。共享包装本身使速度优先产物缩小约 16.1%；再选择尺寸优先后，相比原速度优先产物共缩小约 36.0%。没有裁剪未知原生方法槽，也没有使用 UPX。Release Win32/x64 构建、尺寸优先三档差分/导出调用、速度优先及尺寸优先语义回归通过。没有进行代表实际生产负载的吞吐性能基准，因此默认保持速度优先。

12,018,688 字节的尺寸版通过取色器真实取色、颜色标签、哈希、OpenCV、二值化及最后图片测试按钮的烟测，拖拽捕获/释放通过。拖拽验收直接检查 Win32 鼠标消息和捕获状态，不依赖优化器可能改变的函数机器码偏移。

## WFUI 兼容性回归修复

WFUI 启动问题在 `baseline` 下也能复现，定位到通用运行时的缺省参数和消息处理，并非仅由共享包装或 `/O1` 引起：

* 可空字节集转交非可空形参时，缺省标记错误传入支持库，导致取字节集尾部操作访问空指针。非可空形参现在使用具体值。
* 缺省数组作为引用参数传递时丢失声明类型和数组属性，导致成员数查询返回非数组结果，信息框跳过按钮创建。绑定时现在保留声明类型、数组属性及可空状态。
* `NRS_DO_EVENTS` 未派发消息，启动动画等待定时回调而无法结束。现在处理当前线程消息队列，并保留 `WM_QUIT` 供外层消息循环退出。

以上修复不匹配工程、模块或支持库名称。`TestDirectCompilerSemantics.ps1` 新增缺省字节集转发、缺省数组引用转发及有超时限制的定时消息派发测试，已在 baseline/speed 和 typed/size 下通过。Release Win32/x64 构建及 x64 三档差分和 DLL 导出调用测试通过。

原始 `eproj/wfui.e` 的 typed/speed 与 typed/size 产物均通过 `TestWfuiRuntime.ps1`：窗口绘制、文本输入、菜单、关于框、最小化/恢复、最大化/恢复、取消关闭及确认退出。产物与截图位于 `temp/wfui-size-regression/wfui-final-{speed,size}.exe` 和对应 `verified-final-*` 目录。WFUI 源工程没有修改。

取色器沿用此前修复的 `temp/yunimage-diagnosis/repaired-source` 副本，重新编译两种策略，产物为同目录下的 `final-compat-{speed,size}.exe`。两者均通过真实屏幕取色、颜色标签像素、鼠标捕获/释放、哈希、OpenCV、截取二值化和三个“使用最后的”按钮烟测；按钮测试保持响应并以状态 0 退出。最终 speed 为 15,938,048 字节，size 为 12,188,160 字节；原始 `.e` 未被覆盖。此轮未执行全量模块拆包回包测试。
