## 修复依据与设计

1. **历史符号是身份，不是名字猜测。** 原文件的可丢失段保存被删除声明的显示名称，原生表达式仍引用其 ID。增加方法级引用来源，保存 ID、所属类型、支持库编号与可确认的类型。显示层仍使用 IDE 名称；内部别名只参与语义绑定，不从 `_Local_` 等名字格式反推编号。
2. **方法中的重复出现位置有区别。** 对未改变的方法进行双向子序列对齐，只恢复前后匹配一致的出现位置。添加注释不再误报重复条件的身份歧义；删除不可区分的重复行仍拒绝猜测。普通整行注释不再因形状相同而误判成跨方法搬运的隐藏引用。
3. **停用表达式和注释分开处理。** 从原生语法节点记录停用状态，内部显式表达，目录仍显示 IDE 原文。空停用流程不会被连续注释吞掉，停用调用重新生成带停用标志的字节码。没有身份映射的流程页也保留当前语法，避免未编辑回包变化。
4. **调用绑定不依赖已经丢失的接收对象类型。** 对原文件已经记录的支持库调用、本地方法调用及外部类型成员，保留库号、命令号、成员编号和所属类型；支持库缺失时仍可重建原来已有的引用。当前真实窗口控件登记为已声明成员，避免把它们误当作历史引用。链式调用后的历史成员可使用原生所属类型恢复。
5. **导入声明完整性。** 外部模块缺失时，已有路径恢复了类、结构、方法却漏掉 DLL 声明。现从原工程导入表恢复 DLL 声明及参数。它们是声明数据，不是旧的本地方法字节码。导入子 ID 分配避让全部已观察的 ID；结构保留原始符号名，支持类／结构同名时的显示别名。
6. **常量备注按格式版本解释。** 现代目录中第四列的 `公开,` 是备注，不能凭文字内容猜成旧五列格式的公开标志；旧格式兼容仅对明确的历史版本启用。
7. **窗口默认空载荷是合法状态。** 原属性满足 XML 目标值时，包括空载荷默认态，都不调用无必要的第三方保存接口。实际改动仍应用属性并在序列化后重新读取核验，不放宽校验。原始属性载荷保留为编辑基底。调查中“只保留非空载荷即可解决”的初步判断被复测否定，最终修复覆盖空载荷的无修改路径。

目录格式版本由 7 升为 8，用于保存新增身份信息。上述规则基于格式、语法节点、声明所属关系和原生编号，没有针对样例内容的替换规则。
